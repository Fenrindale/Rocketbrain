SQL Rename retains current-document local alias/CTE/output changes as reversible WorkspaceEdit edits with post-edit rebinding. A separate reviewed workflow renames physical InnoDB tables/columns using one quoted DDL on an owned connection, then verifies the selected definition and visible foreign keys. DDL is not transactionally undoable and is not atomic with subsequent editor changes. A result that cannot be verified is reported as unknown and is never retried automatically.
The physical rename requires the relevant DDL and LOCK TABLES permissions. Active/manual/unknown console state blocks applying DDL. Known stored dependencies, relevant object grants and unsupported expression/CHECK/partition column cases require separate migrations. Hidden visible definitions reject the default apply and require a separate explicit unverified-dependency acknowledgment; no complete cross-schema, dynamic or application reference proof is claimed.
Project SQL references and source rename plans cover supported resolved SELECT statements in bounded local query roots. Unsupported or incomplete source coverage blocks a combined source update; a separately reviewed database-only change remains explicit. Embedded Java/dynamic SQL and complete migration analysis are outside this index. Editor changes remain unsaved and are not atomic with database DDL.
Server table browsing uses bounded OFFSET pages, catalog-backed sort identifiers, primary-key tiebreakers and typed parameterized AND filters. Concurrent changes can move rows between pages; tables without a primary key expose only the first page. Saved filters and cross-page snapshot guarantees are not provided.
Java refactoring uses public JDT protocols and an owned private preview/apply workflow with source, project, resource, trust and cancellation guards. Existing method/local/field extraction, local inlining and organize imports remain supported. Bounded extensions move one plain public Java class file within the same observed project/source root, change simple non-polymorphic method/constructor parameter lists and direct callers, or delete unused plain private methods/package-private final class files. A standard read-only document-symbol lifecycle barrier precedes signature requests; mutation requests are not automatically retried. Text edits remain unsaved; native resource moves/deletions affect disk. Text/move Undo and explicit session-only, non-overwriting original-byte file restoration are separate workflows; file Ctrl+Z after its editor closes is not claimed. Arbitrary file/member/project moves, full signature/hierarchy/framework contracts, external clients, computed reflection and arbitrary engine-command execution remain outside this scope.
Schema snapshots contain bounded visible metadata and server identity, not row data. Metadata reads are not an atomic server snapshot; definitions/defaults/comments may contain application information. Comparison and selected additive SQL generation never apply a migration. Supported plans cover simple InnoDB table creation, nullable NULL-default column additions and ordinary non-unique BTREE index additions. Changed/destructive definitions and complex dependencies require separate migration work. Explicit fresh revalidation does not make exported SQL enforce its fingerprint at later execution; DDL can lock, fail or commit implicitly and is not atomic across steps.
Bulk grid paste, duplicate-row and UTF-8 CSV/TSV import only stage local changes. Explicit source-column mapping, unquoted opt-in NULL tokens and exact text distinguish empty strings from SQL NULL. Protected keys/columns, unchanged model/draft checks and bounded input remain enforced. Review SQL, Apply Reviewed Changes and explicit Commit/Roll Back retain the existing conflict/transaction pipeline. Legacy XLS remains unsupported. The bounded grid draft path retains its limits; a separate reviewed streaming command handles larger files.
SQL scripts are preflight checked for supported boundaries, observed SQL mode, execution policy and typed values before user statements run. This does not prove universal server SQL validity. Values use binary prepared binding, never SQL string interpolation. Exact integer/decimal/calendar/JSON values are validated and bound as text; target columns or explicit CAST determine database types. Boolean, SQL NULL and binary values are separately bound. The same-console queue runs statements in order, stops on the first error and never automatically retries, commits or rolls back. DELIMITER, routines/CALL, executable comments and explicit transaction/session-mode SQL inside scripts are unsupported. DDL requires concrete review and explicit implicit-commit acknowledgment; active pre-existing transactions block DDL scripts. A batch is not atomic, and earlier acknowledged changes may remain committed after later failures.
Typed-parameter reuse is explicit, same-source/connection/SQL-mode, bounded RAM only and cleared on document/extension close. Public review metadata omits bound values, but actual SELECT result rows can contain and retain returned parameter values. Cancellation and timeouts preserve explicit reconnect/unknown-outcome semantics. Aggregate retained results are limited separately from each statement's row/byte limit.
Reviewed selected additive schema plans can be applied on a dedicated owned write connection after explicit implicit-commit acknowledgment. Private one-shot SQL, fresh identity/mode/schema checks, per-existing-table WRITE locks and per-step post-observation preserve explicit applied/failed/not-run/uncertain outcomes. No console transaction is committed; running/queued and unresolved/manual console work blocks apply. Advisory coordination does not exclude every external DDL; multi-step application is not atomic and has no automatic retry or reverse DDL.
XLSX import reads a bounded local OOXML archive through pinned yauzl3.4.0 and saxes6.0.0 plus their runtime dependencies. No Office/Excel or spreadsheet authoring runtime is bundled. Exact stored numeric text and supported1900/1904 dates are preserved; the fictitious1900 leap day is rejected. Blank-cell policy is explicit and distinct from explicit empty text. Formula cells are rejected by default; opt-in cached results may be stale and are never evaluated. External relations, macros, legacy XLS/XLSM and selected merged cells are unsupported. Staged changes retain the normal reviewed transaction pipeline; no import automatically writes data.
The saxes npm archive omits its release license text. The complete upstream v6.0.0 notice is pinned from commit211fa0ebec9b628affc09219199639887174bfc3 and included in THIRD-PARTY-LICENSES.txt with its ISC and inherited notices. Runtime dependency versions, lock integrity and license hashes are separately recorded.
Complex/destructive changes use supported typed InnoDB shadow rebuilds or retained table removal. Original schema/data is retained and operation state is recorded in an owned database journal. Automatic compensation and explicit recovery inspect object ownership, structure and row digests before restoring originals; intervening live data is not silently overwritten. MySQL multi-name RENAME and MariaDB stepwise ALTER RENAME have different publish boundaries. No universal cross-step atomicity, hidden dependency absence, blind DDL replay or automatic deletion of retained originals is claimed. Unsupported dependency graphs and conversions are refused. Legacy unverified-dependency acknowledgments do not bypass complete affected FK/trigger/view metadata for new previews. New CHECK names can differ while retained originals coexist.
Large CSV/TSV/XLSX imports scan and validate a pinned source and target, then stream bounded batches through one owned transaction. Explicit final Commit/Roll Back is required; validation/error/cancellation before commit rolls back all batches and unconfirmed imports expire after five minutes. A lost commit acknowledgment remains uncertain and is not automatically retried. Source identity/hash, mapping/types, SQL mode, schema and workspace context are rechecked. Streaming is bounded by file/metadata/row/batch/time caps; it does not load the entire worksheet or stage all rows in the grid. Formula/macro/external-data execution and automatic resume are excluded. Existing bounded grid import controls retain their separate limits.
Supported dependency-aware rebuilds capture typed current-server FK graphs, restricted original trigger/view definitions and their security/SQL/character context. Explicit approval covers journaled dependency transitions and owned application-write guards. Original user triggers do not execute during shadow copy; FOREIGN_KEY_CHECKS is not disabled. Guarded restoration checks current definitions, rows and counters and never blindly replays uncertain DDL. Current-server normal client DML fencing is not distributed replication or administrator coordination; unsupported/hidden affected definitions are refused rather than silently recreated with different privileges.
Finite per-column type conversion rules are reviewed and journaled. Exact numeric, calendar, Boolean/BIT, UTF-8, JSON, enum/set and exact finite float strategies have explicit validation; decimal quantization requires a selected half-even/truncate policy and separate approval. No arbitrary client SQL/functions/code, silent fallback CAST, locale/timezone guessing, nonfinite or unapproved precision loss is accepted. Original values remain available through retained-table recovery.
Multi-server schema coordination is a durable guarded saga over private live services with participant journals and retained write fences. Implicit-commit DDL is not an atomic distributed XA transaction. Recovery reconciles decisions/objects rather than blindly replaying SQL; passwords/configs are not journaled. A same-server Rocketbrain coordinator is acquired before the existing active-schema coordinator for rebuild/recovery; this does not coordinate external administrators or other servers. Same-server cross-schema graph operations use schema-qualified identities and bounded structured trigger parsing before restoring observed definitions. Current-account global metadata visibility and existing affected-schema DDL rights are required; the product never grants permissions. Stored-program analysis supports bounded typed loop/label and current-definer CALL closures plus bounded prepared-state propagation and explicit-invocation SQL analysis. Trigger-reachable dynamic SQL and unsupported executable grammar are refused; analysis never calls user programs. New YEAR, canonical hex/base64 and explicitly reviewed UTC TIMESTAMP strategies preserve original recovery values; named-zone/DST inference remains unsupported. Explicit bounded2D WKT/WKB/geometry family conversions use reviewed SRID0/4326 and xy axis rules; exact coordinates are default and nearest-even WKT requires loss approval. Explicit EPSG4326/3857 vertex reprojection and supported single-column NOT NULL InnoDB SPATIAL/R-tree rebuilding are added. Projection requires separate loss approval and preserves originals; arbitrary SRS, datum grids, densification, dateline/topology repair and geometry-to-WKT remain unsupported. UTC applies only to the dedicated owned operation connection, not the user console.
The extension version is 0.24.0; the separately provisioned Java testing runtime component remains 0.9.0 with JUnit6.0.3, TestNG7.11.0 and JaCoCo0.8.16. No new engine binaries are included in the VSIX.

Contextual dynamic analysis uses bounded explicit invocation/session inputs and proven prepared-state paths without executing analyzed programs. Case-specific certainty is never reused as universal migration proof. Native cross-server atomic DDL is unavailable: explicit atomic requests are rejected before connections/review/DDL with no saga fallback. Offline/read-only observed capability reports distinguish documented single-statement guarantees from actual XA/implicit-commit/partial-change probes. Crash atomicity was not experimentally proved.
Bound-value summaries are type/hash redacted, but resolved SQL text and literals derived from explicit inputs may appear in the readonly report. Resolved templates support one statically named SELECT/INSERT/UPDATE/DELETE; dynamic CALL, CTE, UNION and general JOIN are outside the supported grammar.
