# Saved ACP workspace sessions

Configure the local OpenCode executable in `rocketbrain.acp.workspaceEditOpenCodePath` and set the numeric loopback endpoint and model in `rocketbrain.localCodeModel`. In a trusted local workspace, choose **Rocketbrain: Start or Continue a Saved ACP Session**. Select **Start a Saved Session** and enter a label and prompt, or choose an existing session and enter the next prompt. Review the executable fingerprint, model destination, selected session, and new prompt in the approval dialog. [ACP v1 session setup](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/protocol/v1/session-setup.mdx)

On continuation, a new OpenCode process loads the selected conversation with `session/load`. The transcript shows replayed turns separately from the new reply. OpenCode receives no editor file, terminal, MCP, or database access through Rocketbrain. The approved local model receives the prior conversation context. The same workspace storage, reviewed executable bytes, loopback endpoint, and model are required to continue. [OpenCode ACP](https://opencode.ai/docs/cli/acp)

The extension keeps up to eight sessions per workspace and eight completed turns per session. AES‑256‑GCM protects each completed OpenCode checkpoint using an independent workspace SecretStorage key. The peer uses a private temporary working directory during a turn. **Recover Saved ACP Workspace Storage** checks the recorded process owners before clearing an abandoned lease and discarding unfinished peer files. A failed or cancelled turn leaves the previous completed checkpoint for an explicitly approved continuation. **Remove a Saved ACP Session** deletes the chosen checkpoint after confirmation.
