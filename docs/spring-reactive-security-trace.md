# Reactive Spring Security trace

Use **Rocketbrain: Prepare Local JVM Observer** in a trusted workspace. Set `securityReactiveTrace` to `true` in the generated observer configuration, add the displayed JVM arguments, and restart the WebFlux application. The agent requires an independent JDK 25 or later. Connect with **Rocketbrain: Connect Local JVM Observer** using the loopback URL and private token. Exercise a request in the running application, then open **Rocketbrain: Inspect Reactive Spring Security Trace**. Run the command again to refresh the samples.

The view lists tested chain candidates, the observed selected chain, configured filter classes in order, and the subscribed prefix observed in Spring's default reactive filter chain. When captured, it displays the response status, terminal signal, and duration. An absent status means the application had no explicit status available to the probe. Web verification reflects the result of Spring's `ReactiveAuthorizationManager.verify` call. A passed verification can include a manager that completed without returning a decision. The method section lists the framework's before or after authorization event, declaring type, method signature, and outcome.

Correlation uses a private Reactor Context key on the application's request subscription. Supported child operators can change schedulers without mixing concurrent requests. The observer keeps up to 16 completed samples with bounded candidate, filter and method lists. It omits request paths, queries, headers, credentials, role labels, method arguments, return values, body data, and exception messages. The observer endpoint is local and requires its own token.

This scope was verified with Spring Boot 4.1.2, Spring Security 7.1.2, Spring Web 7.0.10, and Reactor Core 3.8.8. The agent checks the exact bytes of supported probe classes before rewriting them. Other builds, module-isolated classes, custom decorators, and detached subscriptions can yield partial evidence. The trace does not reconstruct application policy or predict authorization for unexecuted inputs. The independent Servlet observer retains its own opt-in.
