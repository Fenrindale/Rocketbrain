# Docker workbench

Install the Docker CLI and start a daemon available through an existing Docker context. Open the **Docker** view in a trusted workspace and choose **Select Docker Context**. The selection shows the endpoint before it connects and applies to the current extension session.

- **Containers** shows the selected daemon's running and stopped containers. Select a container to read its latest 200 log lines. Use **Manage Docker Container** to review and approve a start, stop or restart of the selected full container ID.
- **Images** lists local image tags and digests.
- **Compose** uses the Docker Compose CLI to list projects and the daemon's project labels to inspect member containers.
- **Open Compose Override Draft** selects a saved base YAML file and up to seven ordered overrides from one local workspace. Choose one override to edit in an untitled draft. Run **Review Compose Override Draft** to compare the resolved current and proposed service models, then apply the reviewed text to the chosen override's editor and save it there.
- **Inspect Registry Manifest** looks up a registry-qualified tag or digest with the Docker CLI after you approve the request. Docker uses its existing registry sign-in, when configured. The CLI must support `docker manifest inspect`.
- **Check Registry Repository Permissions** checks a private Registry v2 Bearer account against a selected repository. Add a profile in User Settings under `rocketbrain.docker.registryPermissionProfiles`. Supply the registry HTTPS origin, configured token endpoint, expected audience (`service`), expected `issuer`, and an absolute `signerPath` to the public RSA signer PEM certificate. For a private HTTPS CA, set its public `caPath`. Both endpoints must validate against that CA when configured.

The listing is limited to 500 objects per category. The Docker workbench checks the context endpoint and the daemon identity again before it sends commands. Lifecycle approval expires after one minute and remains tied to the exact container and reviewed state.

Choose a repository and manifest such as `team/app:stable` or a digest. The permission review shows both HTTPS endpoints and the signer fingerprint before requesting masked account credentials. It verifies a short-lived RS256 signed grant for only that account and repository. The result reports whether the exact manifest was readable and whether the issuer granted push. Push is a grant result, while actual read access is checked against the registry. Credentials and signed tokens are transient. Vendor ACL edits and registries with other authentication mechanisms have separate workflows.

The Compose draft review uses the local Compose CLI with explicit ordered temporary files. It compares the static model with interpolation disabled and redacts environment values, build arguments and secret definitions. Changes to any saved Compose file or the draft invalidate an in-progress review. Only the selected override is opened for editing after approval. The review supports ordinary Compose merge tags and explicit configuration files. Projects using `include`, `extends`, `env_file` or `label_file` require a separate review of those dependencies.
