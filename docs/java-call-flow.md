# Trace Java value flow across calls

In a saved Java file in an imported project, place the cursor on an argument, parameter, local value, call or return keyword. Run **Rocketbrain: Trace Java Value Across Calls**. Choose **To Here** to see the inputs to the selected value or **From Here** to see its uses. Select a result to open its precise source range. **Trace Java Local Value** remains available for a single straight-line method.

Javac resolves each overload. The trace follows primitive and String arguments into their parameters and follows return values into the calling expression. It spans saved project sources and supports direct static calls and same-instance calls with private or final dispatch. When multiple call sites reach the selected method, choose an individual caller. This keeps each site's values separate, even if two invocations occur in the same method. [Java method invocation specification](https://docs.oracle.com/javase/specs/jls/se25/html/jls-15.html#jls-15.12)

A supported `if/else` or ternary shows the condition and possible value branches. For statement branches, the graph follows each assignment to its next use and joins definitions only where the paths continue. Early returns feed the call result separately. Known booleans, scalar literal comparisons and String nullness pass through the selected caller context and can remove a branch. Direct boolean and String null tests can also narrow the variable within an arm. An unknown condition leaves both possible paths in the graph. [Java specification for if statements](https://docs.oracle.com/javase/specs/jls/se25/html/jls-14.html#jls-14.9)

The analysis covers bounded blocks with scalar locals, simple assignments, finite `if/else` and value returns, up to five active frames and 48 nested calls. Recursive calls, dynamic dispatch, dependency-only bodies, heap and alias flow, exception paths, loops and `switch` require a different analysis. Run the trace again after changing a reviewed source.
