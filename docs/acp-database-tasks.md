# Database ACP task review

Configure the stable ACP v1 peers in `rocketbrain.acp.databaseAgents`. A `stdio` entry uses a trusted local executable and optional literal arguments. The `opencode-local` adapter starts the selected OpenCode executable with `acp --pure` and uses the numeric loopback model endpoint and model configured in [Local SQL assistant settings](local-sql-assistant.md). Set only the label, executable, and adapter for OpenCode. [ACP session setup](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/protocol/v1/session-setup.mdx) [OpenCode ACP](https://opencode.ai/docs/cli/acp)

In a trusted workspace connected to MySQL or MariaDB, open **Rocketbrain: Review Database ACP Tasks**. Choose the foreign-key route and columns, enter two or three requests, and assign each to a configured peer. Review the exact executable, arguments, file fingerprint, and schema request before starting the tasks. Use **Cancel** to stop one task while the others continue. Compare results, then choose **Review SQL** or **Reject** for each draft. **Open in SQL Editor** opens the accepted draft. **Inspect Estimated Plan** separately approves a read-only server estimate for the exact draft and checks that the approved schema and key definitions still match.

The task lane sends the reviewed request and selected schema metadata. It starts each peer with its own temporary working directory and environment and exposes neither editor file and terminal APIs nor MCP servers through ACP. The OpenCode adapter selects a loopback model and denies external tools in its private configuration. Custom `stdio` peers run as the operating-system account and are responsible for their own backend configuration and process behavior. Configure only trusted executables. Keep credentials out of arguments and requests.

Automatic data execution is outside this workflow. Rocketbrain builds the draft from supported columns, aggregates, grouping, sorting, and a reviewed route of two to four same-schema InnoDB tables. User review is required because an agent can misunderstand a request. The OpenCode integration fixture uses a separately verified OpenCode 1.19.6 binary with an owned local llama.cpp and Qwen endpoint, without an external actor or service account. [OpenCode 1.19.6 release](https://github.com/anomalyco/opencode/releases/tag/v1.19.6)
