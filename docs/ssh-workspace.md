# SSH workspace processes

Open a trusted SSH workspace with the selected profile and verified host key. Use **Open Reviewed SSH Workspace Terminal** to review the host and physical workspace directory. The terminal opens an interactive shell in that directory. Commands run when you type them. The terminal uses UTF-8 text and its initial SSH terminal size.

Use **Start Reviewed SSH Java Analysis** to select the independent JDK 25 or newer and the extracted Eclipse JDT LS distribution on the same host. Open Java files through the SSH workspace tree to use hover, diagnostics and Go to Definition. Definitions open in the same SSH workspace. If someone changes a source on the server, reopen its editor to match the server before requesting Java information.

The Java process serves read-only saved source navigation. It uses its own temporary state without automatically importing Maven or Gradle builds. Local Java editors keep their local engine. **Stop SSH Java Analysis** stops the language process. **Close SSH Workspace** closes its owned processes and file connection. Open the workspace again after a host-key file change.

**Attach Reviewed SSH Java Debugger** attaches to a running, same-account HotSpot JVM on a Windows or Linux SSH host. Start the JVM with its JDWP listener on IPv4 loopback and its reported working directory set to the reviewed SSH workspace. Select the corresponding saved local Java source and supply the exact remote PID, port and independent JDK 25 directory. The command verifies the JVM lifetime and socket ownership, then compares the local source with the file at the same relative path on the SSH host. It derives the local Java package root from that source. On Linux it also checks the kernel working directory, matching user, PID and network namespaces, and the target process's socket descriptor through `/proc`.

The reviewed relay accepts one loopback client, verifies the remote socket owner before sending debugger traffic and closes when the Java debugger disconnects. Editing the selected local source closes the reviewed attach. **Disconnect SSH Java Debugger** releases its relay and keeps the JVM running. Compile the remote class from the matching source before setting breakpoints. The selected saved source is checked before attachment and can be used in the local editor.

Open a saved remote Java file under `src/main/java` and choose **Compile Reviewed SSH Java Module**. Supply the remote independent JDK 25 directory and any required dependency JARs as comma-separated paths relative to the SSH workspace, for example `/libraries/spring-jdbc.jar`. Review the physical host and directory, source set and explicit classpath before compiling.

The compiler checks the reviewed source bytes, classpath and JDK again before running. It accepts up to 128 Java files in conventional ASCII package paths and up to 24 explicit workspace JARs. It uses Java 25, compiles with annotation processing disabled and fingerprints the resulting class files in temporary storage. Cancel from the progress notification to stop the owned compiler. Results show the class count or compiler errors, and an unambiguous diagnostic can open the matching saved remote source. Temporary inputs and class files are removed. Maven or Gradle dependency resolution, generated code, external JAR manifest classpaths and artifact deployment require separate workflows.
