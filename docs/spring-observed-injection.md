# Observed Spring dependency resolution

Prepare the local JVM observer in a trusted workspace. Enable `springAutowireTrace` and list the application packages in `springAutowireTracePackages` before restarting. Connect to the JVM and run **Inspect Observed Spring Constructor Injection**. Each event identifies the constructor class, parameter index and type signature, requesting Bean, and observed Spring context. Context keys distinguish reused display names.

For a supported constructor resolution, the observer records a selected local Bean definition and any name hint returned by Spring’s resolver. Actual ambiguity is displayed separately. **Open Observed Spring Constructor Parameter** checks a chosen saved Java file for a unique matching declaration and opens the parameter. The source match covers its declaration shape and does not compare source revisions. [Spring qualifier and candidate semantics](https://docs.spring.io/spring-framework/reference/core/beans/annotation-config/autowired-qualifiers.html)

**Inspect Observed Spring Field and Method Injection** uses the same opt-in configuration. It captures the approved application's field and method parameter resolutions through the ordinary Spring autowiring processor. A result shows the local Bean name where observed, scoped by the BeanFactory key. Confirmed empty optional resolutions and actual ambiguity have distinct states. The list for array, collection and map dependencies contains bounded names that Spring supplied to the aggregate resolution, in alphabetical order for easier comparison. **Open Observed Spring Injection Source** checks a saved Java file for a matching annotated field or method parameter.

Each method event describes a parameter's resolution. Spring can skip invoking an optional method when a later parameter is missing. The trace was verified with Spring Framework 7.0.10 and retains up to 48 events per view. Coverage is limited to ordinary resolutions through the observed Bean factory with supported application types. Ancestor-only definitions, cached shortcuts, AOT, and lazy providers may leave partial or no evidence. Inspection reads retained events without calling Bean suppliers or replaying dependency resolution. Bean values and failure messages are omitted. [Spring @Autowired behavior](https://docs.spring.io/spring-framework/reference/core/beans/annotation-config/autowired.html)
