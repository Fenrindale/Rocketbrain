# Inspect JPA entity graphs

Connect the local JPA provider observer and run **Inspect JPA Entity Graph** in VS Code. Choose the running factory and a registered name. The report shows the root entity and nested attribute paths returned by the Jakarta Persistence runtime. A registration with no observed application can still be inspected. Use **Check an Expected Graph Name** to verify whether a name is registered in the selected factory. [Jakarta Persistence factory registration API](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/entitymanagerfactory)

With performance capture enabled, the report links retained Hibernate SELECTs with the same factory, graph name, root type and complete path set. Each link includes the Spring request ID, SELECT position, phase and the effective FETCH or LOAD mode. **Inspect Hibernate Fetch Activity** shows the graph on that SELECT alongside its SQL template and typed bind positions. Spring Data can replace a named annotation value with dynamic `attributePaths`. Dynamic graphs appear separately in fetch activity. [Spring Data JPA entity graphs](https://docs.spring.io/spring-data/jpa/reference/jpa/query-methods.html)

Registration inspection reads the running factory’s metadata and the observer’s retained evidence. It opens no session, runs no SQL and keeps no row or bind values. Hibernate ORM 7.4 was verified for a named value-subgraph and a separate dynamic graph. Treated and map-key subgraphs, oversized registries and exhausted sample bounds may leave partial coverage.
